T3 Code 与 Orca：协作为什么难

同时拉起多个 Coding Agent 并不难。难的是让它们顺畅地委派任务、互相通信、交接上下文，并在出错后可靠恢复。T3 Code 和 Orca 都在现有工具之上加了一层 Agent 编排层，目标一致，底层走了两条路。

  • T3 Code · 运行协议、会话、交接、事件流
  • Orca · 依赖、派工、结构化通信、Worker 生命周期

这一页先看协作为什么难，以及协调者和编排器。T3 Code、Orca 和对照在后面三页。

  1. 01协作为什么难
  2. 02协调者与编排器
  3. 03–06后面三页

01

多 Agent 协作难在不断线

Codex、Claude Code、Pi、OpenCode 各自都有独立的会话、上下文和工具体系。编排层要补上的，是它们之间这四段容易断开的路。

02

先分清协调者与编排器

多 Agent 协作通常拆成两层。上面决定怎么分工，下面把决定稳稳落地。

Coordinator · 协调者 本身往往也是 Agent
  • 理解需求
  • 拆解任务
  • 指派执行者
  • 验收结果
↓决策交给下层落地
Orchestrator · 编排器 底层运行时
  • 拉起 Agent
  • 投递消息
  • 维护状态
  • 管理依赖
  • 失败重试
